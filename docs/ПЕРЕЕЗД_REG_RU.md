# Переезд рабочего сайта на Reg.ru

Пошаговая инструкция для того, кто будет выкладывать сайт. Код лежит в папке `site/` репозитория.

## 1. Тариф

Подойдёт любой хостинг или VPS Reg.ru, если на нём есть:

- PHP 8.2 или новее;
- расширения PHP: `pdo_sqlite`, `gd` (с поддержкой WebP), `mbstring`, `curl`, `openssl`, `fileinfo`, `exif`;
- Apache с `mod_rewrite` или nginx;
- HTTPS (бесплатный сертификат Let's Encrypt в панели Reg.ru);
- планировщик задач (cron).

## 2. Загрузка

1. Загрузите на хостинг папку `site/` целиком, например в `~/platforma/`.
2. Корнем сайта для домена p.forma196.ru назначьте папку `site/public`. Это обязательно: всё остальное (`app/`, `data/`, `tests/`) не должно открываться из браузера.
3. Дайте веб-серверу право на запись в две папки: `site/data` (там база) и `site/public/uploads` (фото из админки).
4. **Apache**: файл `site/public/.htaccess` уже есть. **nginx**: в настройке сайта все запросы, которые не файлы, передайте в `index.php`:
   `location / { try_files $uri /index.php?$query_string; }`
5. Запретите отдачу файлов `*.sqlite`. В Apache это уже сделано в `.htaccess`.
6. Лимиты загрузки фото заданы в `site/public/.user.ini`: файл до 25 МБ, за раз до 100 МБ, память 512 МБ. Если хостинг не читает `.user.ini`, выставьте эти значения в панели Reg.ru («Настройки PHP»). Иначе крупные фото из админки получат отказ «больше, чем разрешает сервер».
7. Проверьте, что сайт видит настоящий IP посетителя. На хостинге с nginx перед Apache это обычно так, но если в журнале заявок у всех один и тот же адрес, лимит «5 заявок в час» и блокировка входа будут срабатывать на всех сразу. Тогда попросите поддержку Reg.ru передавать `X-Real-IP`.

## 3. База и первый вход

Все команды выполняются по SSH из папки, где лежит `site/`.

```
php site/app/cli.php migrate              # создать таблицы
php site/app/cli.php bundle               # собрать assets/js/app.js из site/src/js
php site/app/cli.php seed                 # стартовые данные (демо-квартиры, проекты домов) — по желанию
php site/app/cli.php user:add admin admin # первый администратор; пароль выведется один раз
```

Войдите в админку: `https://p.forma196.ru/admin/`.

Сразу смените пароль: внизу меню админки — «Пароль» (не короче 10 символов, без логина). Пока пароль слабый, админка напоминает об этом жёлтой плашкой. Менеджерам пароли создаются случайными; каждый может сменить свой там же.

## 4. Настройки в админке

Раздел «Настройки» (виден только администратору):

- телефон, часы, юрлицо, домен;
- цены ремонта, тёплый контур, программы ипотеки;
- **Telegram**:
  1. создайте бота у @BotFather и вставьте его токен;
  2. добавьте бота в чат менеджеров;
  3. укажите `chat_id` этого чата;
- **почта**: адрес для заявок. Если оставить пустым поле SMTP, письма уйдут через `mail()` хостинга. Если с `mail()` письма не доходят, укажите SMTP почтового ящика (Reg.ru: `mail.hosting.reg.ru`, порт 465);
- **CRM**: пока выключена. Когда появится API, включите и укажите адрес и ключ. Формат запроса меняется в одном месте: `site/app/leads/deliver.php`, класс `CrmChannel`;
- **«Показывать демо-отзывы»** и **«Пометка демо-данные»** — выключите перед запуском.

## 5. Повтор недоставленных заявок (cron)

Заявки сохраняются в базу всегда. Если Telegram или почта не ответили, заявка помечается «не доставлена» и отправляется снова:

- при входе любого менеджера в админку;
- по расписанию, если добавить задачу cron:

```
*/10 * * * * php /путь/к/site/app/cli.php leads:retry
```

## 6. Перед запуском

1. Замените демо-квартиры настоящими: «Квартиры», затем «Открыть», «Снять с сайта» или «Удалить».
2. Выключите демо-отзывы и пометку «демо-данные».
3. Вставьте текст политики обработки персональных данных от юриста в `site/app/templates/privacy.php`.
4. Отправьте тестовую заявку с сайта и убедитесь, что она пришла в Telegram и на почту.
5. Проверьте `https://p.forma196.ru/robots.txt` (должна быть ссылка на `sitemap.xml`) и `https://p.forma196.ru/sitemap.xml`.
6. Добавьте сайт в Яндекс.Вебмастер и укажите `sitemap.xml`.

## Безопасность

Что уже сделано в коде:

- пароли хранятся только хэшем; после 5 неверных попыток вход блокируется на 15 минут (по логину и по IP);
- выход из админки — после 2 часов бездействия и не позже чем через 12 часов после входа; выход — кнопкой, ссылкой не разлогинить;
- все формы админки защищены токеном (CSRF), запросы к базе — параметризованные;
- заголовки безопасности: запрет встраивать админку в чужие сайты, запрет угадывать тип файлов, строгая политика скриптов в админке (CSP), страницы админки не кэшируются и не индексируются;
- заявки с сайта: ловушка для ботов, не чаще 5 в час с одного адреса, тело запроса не больше 64 КБ;
- фото из админки пересохраняются в WebP (метаданные и вложенный код отбрасываются); в `uploads/` скрипты не выполняются;
- в выгрузке заявок в Excel формулы обезврежены;
- ошибки PHP пишутся в журнал, на экран посетителю не выводятся.

Что сделать на хостинге:

1. Включите HTTPS и перенаправление с http на https в панели Reg.ru. После этого сайт сам добавит заголовок HSTS.
2. Убедитесь, что включён модуль Apache `mod_headers` (обычно включён) — он добавляет заголовки и для картинок и стилей.
3. Корень сайта — только `site/public` (см. раздел 2). Проверьте: `https://p.forma196.ru/../data/site.sqlite` и `https://p.forma196.ru/.user.ini` должны отвечать ошибкой.
4. Раз в месяц обновляйте PHP до последней версии ветки в панели хостинга.
5. Резервные копии базы и фото — раз в день (раздел «Резервные копии»).
6. Токен Telegram-бота, пароль почты и ключ CRM храните только в админке («Настройки»), не пересылайте в открытых чатах. Если токен утёк — выпустите новый у BotFather и замените.

## 7. Проверка на сервере

```
php site/tests/run.php          # должно быть «… passed, 0 failed»
```

## Обновление сайта

Загрузите новые файлы `site/` поверх старых, кроме `site/data/` и `site/public/uploads/`, затем выполните `php site/app/cli.php migrate`.

После правок JS в `site/src/js/` склейте `app.js`:

```
php site/app/cli.php bundle
```

## Резервные копии

Достаточно копировать две папки: `site/data/` (база) и `site/public/uploads/` (фото). Делайте это раз в день средствами Reg.ru или cron.
