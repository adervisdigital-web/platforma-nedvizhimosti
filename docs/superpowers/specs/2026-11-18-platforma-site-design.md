# Рабочий сайт «Платформа недвижимости» — спецификация

Дата: 2026-11-18. Статус: согласовано в чате, ждёт проверки заказчиком-исполнителем.

## Цель

Сделать из прототипа `08_Сайт_пример/index.html` (v40) рабочий сайт: данные в базе, админка для менеджеров, приём заявок. Личный кабинет клиента в этот этап не входит.

Сейчас сайт показывается на GitHub Pages как витрина. Позже он переезжает на Reg.ru без переписывания.

**Готово, когда:**

- На GitHub Pages сайт выглядит и работает как v40. Каталог, фильтры, карта и калькуляторы берут данные из JSON. Заявки работают в демо-режиме.
- Локально на PHP работают:
  - база;
  - админка: квартиры, ЖК, застройщики, дома, отзывы, настройки, менеджеры, заявки;
  - приём заявок в базу, Telegram и почту;
  - страницы квартир и домов с SEO.
- Готова инструкция переезда на Reg.ru.

## Решения

| Вопрос | Решение |
|---|---|
| Откуда квартиры | Сейчас их вручную заводят менеджеры в админке. Схема сразу готова к фидам застройщиков (Яндекс.Недвижимость / Циан): поля `source`, `external_id`. Сам импорт фидов в этот этап не входит. |
| Заявки → CRM | API CRM заказчика пока нет. Заявка сохраняется в базе, уходит в Telegram-бот и на почту. Отправка в CRM — отдельный адаптер, по умолчанию выключен. |
| Хостинг | Сейчас — GitHub Pages, только витрина. Позже — Reg.ru: любой тариф, обычный хостинг или VPS. |
| Стек | PHP 8.2+ и SQLite через PDO. Переход на MySQL — сменой DSN. Без фреймворка, без Docker, без Node и сборщиков. |
| Сайт | Вид и поведение как в v40. Прототип разбирается на шаблоны, CSS и JS по разделам. Данные идут через один слой `data.js`. |
| Заявки на GitHub | Демо: не отправляются, показывают «принято» с пометкой «демо». |
| Карта | Пока Leaflet + OSM, как в прототипе. Яндекс.Карты — при переезде, после проверки лицензии. |

## Структура

```
site/
  public/                корень сайта на сервере
    index.php            главная (шаблоны + данные)
    kvartiry/            страницы квартир: /kvartiry/{id}-{slug}
    doma/                страницы домов: /doma/{slug}
    api/                 JSON: items, zk, houses, reviews, settings; POST lead
    assets/css, js, fonts, icons
    uploads/             фото из админки (оригинал + WebP 480/960/2000)
  admin/                 админка
  app/                   db.php, модели, шаблоны (templates/), leads/ (telegram, mail, crm), security
  data/site.sqlite       база — в .gitignore
  data/seed/*.json       стартовые данные из прототипа: 12 демо-квартир, ЖК, 5 проектов домов, отзывы, настройки
  build.php              сборка статики в папку 10_Сайт/ в корне репозитория (GitHub Pages уже раздаёт корень → …/platforma-nedvizhimosti/10_Сайт/)
  tests/                 тесты PHP + адаптеры существующих tools/test_site.py, check_anim.py
```

Прототип `08_Сайт_пример/` не меняется и остаётся эталоном.

**Два режима:**

- **Сервер.** PHP отдаёт страницы и API из базы, админка и заявки работают.
- **Статика.** `php build.php` рендерит те же шаблоны в HTML и выгружает API в JSON-файлы. `data.js` читает JSON по относительным путям. Флаг `DEMO=1`: заявки демо, на всех страницах `noindex`.

## Данные (SQLite)

| Таблица | Поля |
|---|---|
| `developers` | id, name, site, verified |
| `complexes` (ЖК) | id, name, district, developer_id, address, lat, lng, checks (JSON: разрешение, эскроу, сданы в срок, нет банкротства), photos (JSON) |
| `apartments` | id, slug, rooms, area, floor, floors, complex_id, price, discount_pct, finish (with/without), house_status, due (YYYYMM, 0 — сдан), special, photos (JSON, первое — обложка), description, lat, lng, published, source (manual/feed), external_id, created_at, updated_at |
| `houses` | id, slug, line (Северный/Южный/Средний Урал), number, area, motto, color, floors, rooms, ceiling, features (JSON), idea, text (JSON), photos (JSON), plans (JSON по этажам), price_from, sort |
| `reviews` | id, name, text, rating, topic (apartment/house/renovation), is_demo, published |
| `leads` | id, created_at, kind (quiz/callback/viewing/chat), want, budget, area, name, phone, object_ref, slot (для просмотра), ip_hash, status (new/work/closed), note, delivered_tg, delivered_mail, delivered_crm, attempts |
| `settings` | key, value: телефон, часы, реквизиты ИП, ставки ипотеки, цены ремонта за м² (20 / 45 / 80 тыс.), тёплый контур от 75 000 ₽/м², адреса Telegram и почты, флаги demo_data и show_demo_reviews |
| `users` | id, login, password_hash, role (admin/manager), created_at |
| `audit` | id, user_id, at, action, entity, entity_id, diff |

Тексты разделов («Как мы ручаемся», договор, обещания) живут в шаблонах, правит разработчик.

Демо-отзывы (`is_demo=1`) скрыты, когда флаг `show_demo_reviews` выключен. На боевом сайте он выключен.

## Админка (`/admin`)

**Разделы:**

- **Заявки** — первый экран, новые сверху. Кликабельный телефон, статус, заметка, фильтр, выгрузка в CSV, пометка «не доставлена».
- **Квартиры** — таблица с поиском и фильтром, форма:
  - выбор ЖК;
  - загрузка фото перетаскиванием, сжатие и WebP через GD;
  - сортировка фото;
  - «опубликовать / снять» и «копировать».
- **ЖК, застройщики, дома, отзывы** — формы того же вида.
- **Настройки**, **менеджеры** (только у admin).

**Безопасность:**

- `password_hash`, сессия с HttpOnly, SameSite и Secure на HTTPS;
- CSRF-токен во всех формах;
- после 5 неудачных входов — пауза 15 минут;
- журнал действий `audit`;
- загрузки — только изображения: проверка MIME и пересохранение через GD.

Вид: светлый, в стиле бренда, работает на телефоне.

## Заявки

1. **Формы** (заявка в 3 шага, «перезвоните», запись на просмотр, чат) отправляют POST `/api/lead`. В режиме `DEMO` запрос не уходит, показывается «принято (демо)».
2. **Сервер проверяет:**
   - телефон приводится к +7XXXXXXXXXX;
   - скрытое поле-ловушка;
   - форма заполнена не быстрее 3 секунд;
   - не больше 5 заявок в час с одного IP (хранится хэш IP);
   - галочка согласия на обработку ПДн.
3. **Заявка сохраняется в базу** до любой отправки.
4. **Отправка:**
   - Telegram Bot API: что ищет, телефон, ссылка на объект;
   - почта через `mail()` или SMTP — задаётся в настройках;
   - CRM — адаптер `app/leads/crm.php`, интерфейс `send(Lead): bool`, по умолчанию выключен.
5. **Повторная доставка.** Неудачные отправки отмечаются в заявке. Повтор — при входе менеджера в админку и по cron, если он есть.
6. **Ответ посетителю:** «Заявка принята, перезвоним до 21:00». При записи на просмотр он получает файл `.ics`, как в прототипе.

Политика ПДн — заглушка `/privacy`, текст даст юрист.

## Сайт и SEO

- `index.html` v40 разбивается на шаблоны разделов (`templates/sections/*.php`), CSS и JS по разделам. Поведение и анимации не меняются.
- Массивы `ITEMS`, `HOUSES`, `FAQ`, `QUICK`, `PLACES`, `ZKS` и настройки берутся через `data.js`: `getItems()`, `getHouses()`, `getSettings()`…
- **Страницы квартир и домов:**
  - уникальные `title`, `description`, Open Graph;
  - JSON-LD: `Organization`, `Product`/`Offer` для квартиры, `BreadcrumbList`;
  - окно быстрого просмотра на главной остаётся и ссылается на страницу объекта.
- Служебное: `sitemap.xml`, `robots.txt`, канонические адреса.
- В режиме `DEMO`: `noindex` и `Disallow: /`.
- Фото в WebP трёх размеров через `srcset`, ленивая загрузка.

## Проверка

- **Существующие автотесты:**
  - `tools/test_site.py`, `check_anim.py`, `shot_mobile.py` переносятся на новый адрес;
  - статическая сборка проходит их так же, как v40: `errors=` пусто, анимации в реальном времени.
- **Сравнение скриншотов** новой сборки и v40 на 1440, 1920 и 390 px. Расхождения разбираются глазами.
- **Тесты PHP** (`tests/run.php`, без фреймворка):
  - валидная заявка сохраняется;
  - без телефона / ловушка / слишком быстро / превышен лимит → отказ;
  - доставка помечается;
  - админка без входа → 302 на вход;
  - CSRF без токена → 403;
  - квартира из админки появляется в API и на своей странице;
  - снятая с публикации — исчезает;
  - `build.php` отрабатывает без ошибок, и в выходной папке нет `site.sqlite` и персональных данных.
- **Перед публикацией на GitHub** — поиск по выходной папке: нет телефонов клиентов, токенов, `.sqlite`.

## Порядок работ

1. **Разборка прототипа.** Шаблоны, `data.js`, JSON из seed, `build.php` → GitHub Pages. Результат совпадает с v40.
2. **База.** SQLite, миграции, seed из прототипа, API, страницы квартир и домов, SEO.
3. **Админка.**
4. **Заявки.** Сохранение, Telegram, почта, адаптер CRM, повтор доставки.
5. **Финиш.** Полная проверка, `docs/ПЕРЕЕЗД_REG_RU.md`: требования к тарифу, загрузка, права на `data/` и `uploads/`, HTTPS, cron, бот, почта.

## Вне этапа

- Личный кабинет.
- Импорт фидов застройщиков. Схема к нему готова.
- Реальная интеграция с CRM. Адаптер к ней готов.
- ИИ-помощник в чате. Чат остаётся с ответами по темам и создаёт заявку.
- Яндекс.Карты.
- Платёжные функции.
